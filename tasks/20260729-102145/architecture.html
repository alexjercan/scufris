Agent model

Each agent has one job

Agents differ by scope and capability. They do not differ only by name. Tool access is wired by audience, and the operator keeps every irreversible decision.

v0.2.0

Orchestrator

The landing conversation and coordinator.

  • Understands the operator request.
  • Reads projects, tasks, agents, and host facts.
  • Delegates project or host work.
  • Cannot approve host changes.
v0.2.0

Project agent

A backend session bound to one workspace.

  • Runs as the operator in a validated cwd.
  • Uses Codex, Claude, OpenCode, or mock.
  • Requests input or reports back.
  • Has no host mutation tools.
v0.2.0

Host agent

A reserved agent bound to the machine.

  • Inspects host state through typed tools.
  • Can propose typed host actions.
  • Becomes BLOCKED for operator approval.
  • Never receives an approve tool.
v0.2 foundation

Stage specialist

A run resolved from a reusable preset.

  • Plan, work, and review can use different backends.
  • Preset defines tools, permissions, and output.
  • Project policy chooses stage defaults.
  • Full orchestrated launch comes later.

Data ownership

Do not merge different truths

A readable UI can project several sources together. It must still say which source can make the final decision when records differ.

authoritative

Project repository + tatr records

Code, task lifecycle, plan approval, review verdict, dependencies, and task artifacts. Scufris re-reads these files before a future lifecycle launch.

Owner: project / tatr
authoritative

scufris.db

Projects, agent records, session bindings, run outcomes, settings, reasoning, auth, schedules, and app-side host state. One transaction protects multi-record changes.

Owner: Scufris
native detail

Provider transcript

Full Codex, Claude, or OpenCode conversation and backend-native session details. The Agents page remains the direct console for this view.

Owner: backend CLI
v0.2.0

Run activity

Launches, parent-child runs, tools, approvals, artifacts, status, cancellation, tokens, errors, and outcomes. Technical observability, not chat text.

Owner: Scufris run service
proposed

Semantic conversation

A concise, actor-attributed product history shared by browser and Telegram. It points to provider sessions and activity instead of copying every technical event into chat.

Owner: actor-aware spike
authoritative

Root audit and proposal registry

Privileged proposal state, exact apply plan, result, and append-only audit. The app may render this data but cannot rewrite the record.

Owner: scufris-hostd

User flow

Run the flow SDLC on one task

The orchestrator coordinates stages. tatr owns lifecycle truth. A resolved preset chooses the stage agent. Human gates stay explicit.

1. Re-read truth

Before every stage, the server reads current tatr metadata from the registered project.

Prevents stale or illegal launches.
2. Resolve the agent

Project policy resolves the stage preset into backend, model, workspace, permissions, tools, and expected output.

Fails before launch if unsupported.
3. Record the run

The agent-run service records parent, task, stage, worktree, provider session, events, outcome, and artifact links.

Survives refresh and restart.
4. Enforce gates

Plan approval stays human. Review verdict controls work versus compound. Land requires accepted review and proof.

The orchestrator coordinates, not overrides.

User flow

Browser and Telegram

Both channels express operator intent. They use different credentials and renderers, then converge on the same application services.

v0.2.0

Browser path

1 Authenticate

Operator session cookie, CSRF, same-origin checks.

2 Start work

Chat or Project action calls a domain service.

3 Follow live state

SSE replays events after reconnect without restarting work.

4 Inspect detail

Open task, run activity, artifact, or native agent session.

v0.2.0

Telegram path

1 Identify actor

Allowlisted chat ID is the credential. The bot polls out.

2 Run a turn

The Telegram adapter calls the same orchestrator-turn service.

3 Stream compact output

The renderer edits or batches messages within Telegram limits.

4 Decide directly

Host approval buttons call HostApprovalService, not the agent.

Proposed actor-aware model

The future landing conversation can be Scufris-owned and shared across browser and Telegram. Provider sessions remain execution detail and context caches. This is the decision owned by spike 20260729-220835, not a settled v0.2.0 behavior.

Privileged user flow

Host changes stay separate

A coding task can edit a Nix configuration project. Activation is a separate typed host proposal with preview, direct approval, root execution, audit, and rollback.

No shell verb

The caller names a closed typed action. The root helper builds every command argument.

No agent approval

Agent credentials are refused on decision endpoints. Approval belongs to the browser session or allowlisted Telegram chat.

No preview drift

hostd applies only its stored proposal. Drift, expiry, reuse, and missing proposals are terminal refusals.

Component guide

What each part owns

Ownership keeps the design simple. One component makes each important decision; other components call it or render its result.

Component Owns Why
FastAPI assembly Configuration, dependency wiring, lifespan, routers, static files. Application startup stays visible without mixing business logic into one large file.
Orchestrator-turn service One orchestrator turn for web, Telegram, and wake. Every channel gets the same launch and completion behavior.
Agent-run service Launch, resume, cancel, status, outcome, supervisor handle. A run survives the request that started it and has one lifecycle.
Backend adapters Provider CLI arguments, streaming, sessions, capability differences. Scufris stays honest about Codex, Claude, OpenCode, and mock differences.
Diagnostics service Effective backend, model, account, health, usage, memory, tools. Browser and Telegram report the backend actually running.
Project task reader Validated structured tatr metadata and artifact index. Routes and launch guards use the same lifecycle truth.
SQLite stores All app-owned mutable state in explicit transactions. Concurrent agent completions cannot lose each other's updates.
Supervisor + event bus Background work, replayable live events, reconnect, wake. Refresh, disconnect, or Telegram rendering does not kill a run.
HostApprovalService Approve, deny, cancel, revert, decidable state. Web and Telegram cannot drift into different safety rules.
scufris-hostd Typed plans, exact apply, refusals, root execution, audit. The user-level app never receives general root command power.
Future flow coordinator Stage assignments and launch guards above tatr and run services. Coordinates existing truth and services instead of becoming a second workflow authority.

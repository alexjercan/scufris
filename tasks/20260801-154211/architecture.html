Scufris after v0.3.0

The Project page becomes the daily workspace for shipping software. One operator can select a real task, understand its authoritative state, coordinate stage-specific agents, approve human gates, inspect evidence, and move the task through $flow to land.

The product claim

Routine flow work is practical from Scufris without opening task records, provider sessions, or worktrees by hand.

What changed

v0.2.0 services become one operating surface: board, task detail, conversation, runs, artifacts, approvals, and legal next action.

The boundary

Scufris coordinates repository truth. It does not replace tatr, git, provider transcripts, or the root host audit.

Why this is the product

The project page answers where work stands across the repository. The task page answers what this task means, who is acting, what evidence exists, and which decision or action comes next.

End-to-end lifecycle

Run the flow SDLC on one task

The coordinator does not invent another workflow. It reads tatr, resolves the right stage agent, records the assignment and run, and stops only at an explicit context-cut gate. Each gate names its transition, changes nothing on refusal, and can be reconstructed in a fresh session.

01

Understand

Create or select the authoritative task and make scope visible.

02

Plan

Planning specialist writes ordered steps and proof-bearing done criteria.

STOP

PLAN_READY

Approve plan and move to PLANNED, or leave state unchanged.

03

Work

Work specialist uses a sprout worktree, tests first, and reports evidence.

STOP

WORK_DONE

Approve the move to REVIEWING, or leave work in WORKING.

04

Review

Independent review. Approval proceeds directly to compound.

05

Compound

Record lessons, write the retro, close the task, then return LAND_READY.

STOP

LAND_READY

Approve landing the reviewed branch, or keep it intact.

06

Land

Sync, verify, squash-land, run lessons, and report the result.

Changes requested

Review returns to work

Findings become structured review truth. The prior work assignment remains linked. Fixes normally return directly to review. After rounds 3, 6, and later multiples of three, WORK_DONE stops for explicit continuation approval.

<->
Approved

Review unlocks compound

APPROVE moves directly to COMPOUNDING without another stop. Compound closes the task and emits LAND_READY. Landing remains blocked until the operator approves that final action.

Actor and assignment model

Who said it and who did it

Friendly names are not enough. Every meaningful report and every technical event is attributable to a stable actor, assignment, run, and task. The operator can always open the native session.

Human

Operator

Owns intent and human gates.

  • Chooses task and outcome.
  • Approves plans and decisions.
  • Can interrupt or redirect.
Mediator

Scufris

Owns the semantic conversation and coordination.

  • Projects current truth.
  • Explains next action.
  • Routes reports and decisions.
Policy

Stage preset

Defines effective specialist behavior.

  • Plan, work, review role.
  • Backend and model.
  • Workspace, tools, output.
Execution

Agent run

One bounded attempt at one task stage.

  • Parent and correlation IDs.
  • Activity and outcome.
  • Native provider session.
Evidence

Artifact

The durable result of the stage.

  • Plan, diff, proof, review.
  • Task and run links.
  • Safe in-app viewer.

Information architecture

Do not merge different truths

The UI joins these records by stable correlation. It does not flatten them into one chat log or one generic event table. Each record answers a different operator question.

Authoritative

Repository workflow truth

Answers: What stage is the task really in, and what artifact or verdict controls it?

Owned by git, tasks/, tatr records, branches, commits, and worktrees. Re-read before every transition or launch.

Product conversation

Semantic conversation

Answers: What did the operator ask, what did Scufris decide, and what meaningful result did an actor report?

Scufris-owned, actor-attributed, channel-neutral, compactable, and shared by browser and Telegram.

Technical evidence

Run activity and provider transcript

Answers: What executed, which tools ran, what failed, and what did the native agent actually say?

Activity is Scufris-owned and durable. The full native transcript stays provider-owned and opens through Agents.

Enforcement

Approval and audit records

Answers: Who authorized a guarded action, what exact proposal applied, and was any policy refusal raised?

Project gates and root host approvals remain distinct. Root audit stays append-only and helper-owned.

One conversation, two projections

Browser and Telegram agree

Both channels render the same semantic events and pending decisions. The browser gives full context; Telegram stays concise and links back to task detail, activity, or the native session.

Recovery rule

Provider sessions may help resume execution, but they are never the only source of product context. The UI rebuilds from Scufris records plus repository truth, then links to the provider-native transcript for full fidelity.

    Scufris same conversation, delivered by policy

    Delivery policy

    Telegram receives decisions and outcomes: approval requests, gate results, final answers, failures. Reasoning deltas and tool widgets stay on the surface that started the turn. Each delivery is keyed (channel, conversation:seq), so a redelivery after a restart is a no-op.

    Scenario: one task through plan -> work -> review -> compound -> land. Every message carries its actor; only an operator event may satisfy a stop gate. An agent report is shown as an attributed, untrusted quotation. Unavailable actions carry the reason the server would refuse with.

    Limitations: fixtures and a step index. No persistence, no SSE, no real tatr, no provider. One changes-requested round rather than the every-third-round continuation gate; no failure, cancel, or restart-mid-run case.
